# TUI — терминальный клиент

TUI — самостоятельный Linux-клиент. Он подключается к `aniparser_server` по
IPC и получает полные JSON-значения. Он не подключает Core/API как библиотеку
и не читает серверный кэш напрямую.

## Запуск

```sh
out/Debug/src/server/aniparser_server /tmp/aniparser.sock
# В другом терминале:
out/Debug/tui/aniparser_tui /tmp/aniparser.sock
```

Без аргумента клиент использует `/tmp/aniparser.sock`. Он сначала вызывает
`hello` и завершает работу, если сервер не отвечает протоколом версии 3.

Чтобы собрать его, нужен Linux, notcurses-core и nlohmann-json; в проекте они
объявлены через CMake/Nix. Буфер обмена использует любую доступную программу
из списка `wl-copy`, `xclip`, `xsel`; если их нет, URL всё равно виден в меню,
но Enter сообщает, что копирование недоступно.

## Клавиши и переходы

| Клавиша | Действие |
| --- | --- |
| Стрелки вверх/вниз | Переместить выбор или прокрутить длинные ссылки. |
| Enter в Feed/Search | Открыть выбранное аниме. |
| `/` | Ввести поисковую строку; Enter запускает поиск, Esc отменяет ввод. |
| `n` | Показать следующую страницу Search. |
| `f` | Перезагрузить экран Feed. |
| Enter в Anime | Открыть список поддержанных плееров. |
| Enter на плеере/озвучке | Перейти на следующий уровень списка. |
| Enter на эпизоде Kodik или Aksor | Запросить у сервера ссылки всех доступных качеств. |
| Enter на плеере AniLibria | Загрузить серии и доступные HLS-качества по alias аниме. |
| Стрелки и Enter в ссылках | Выбрать качество и скопировать его полный URL. |
| `v` в Anime | Показать viewing order. |
| Esc | Вернуться на предыдущий экран. |
| `q` | Выйти из TUI. |

Копирование сохраняет ссылку потока в системный clipboard. TUI не запускает
видеоплеер. Kodik и Aksor разбираются после выбора эпизода; AniLibria загружает
список эпизодов и HLS-ссылок после выбора источника. Запросы выполняются
синхронно через IPC и могут занять несколько секунд.

## Как устроен клиентский код

- `main.cpp` читает IPC endpoint и вызывает `run`.
- `ipc_client.hpp` подключается к Unix socket, отправляет JSON Lines, ждёт
  ответ с request ID и хранит события, пришедшие не к текущему запросу.
- `tui_app.cpp` владеет экранами, локальными снимками, клавишами и отрисовкой.
- `clipboard.cpp/.hpp` пробует `wl-copy`, `xclip`, затем `xsel` через argv и
  stdin (URL не вставляется в shell-команду).

Feed/Search/Anime сразу отображают полученный snapshot. Когда IPC присылает
`*.updated`, TUI обновляет соответствующий экран/локальную карточку. При
старте TUI подписывается на первую страницу истории через `subscribeHistory`
(20 ID) и остаётся подписанным на IPC-соединении. Каждое `history.updated`
содержит новый snapshot этой страницы; TUI заменяет локальные элементы и
отбрасывает событие с уже обработанным `sequence`. История пока хранится только
во внутреннем локальном snapshot и отдельным экраном не отображается. Карточки
могут прийти позже отдельным событием после API Search. Ошибки Anime refresh видны
в status line и пишутся в
`/tmp/aniparser_tui-anime.log`; поиск пишет ввод и ответы в
`/tmp/aniparser_tui-search.log`.

TUI пока не показывает экраны избранного и пользовательских статусов. Эти
списки доступны клиентам через IPC-команды `subscribeFavorites` и
`subscribePlanned`/`subscribeWatched`/`subscribeCompleted`/`subscribeDropped`;
изменить их можно через соответствующие `add...` и `remove...` методы.

При изменении IPC-формы сначала обновите [протокол](../src/server/IPC.md),
затем этот клиент и README корня. TUI не должен включать заголовки Core или
серверные cache-модули.

Полный `anime.updated` заменяет старую карточку, включая пустые поля. После
смены модели устаревшее вложенное меню возвращается к Details. Возврат из поиска и viewing order
восстанавливает связанную модель и выбор; cold `anime:null` показывает загрузку.
Русский ввод/Backspace обрабатываются по целым UTF-8 code points.

IPC request имеет deadline 100 секунд (видеопровайдер может выполнить несколько
последовательных HTTP-запросов). Во время ожидания экран перерисовывается,
resize обрабатывается; `q` завершает работу, Esc отменяет запрос и отключает
соединение. После timeout/отмены требуется перезапуск клиента. Входной ответ
ограничен 16 MiB; EOF распознаётся явно. Notcurses освобождается и при исключении.

Текстовый клиент использует `notcurses_core_init` и линкует `notcurses-core`.
Multimedia/FFmpeg/SDL и CPR для этого executable не требуются; backend по-прежнему
использует CPR. Это также устраняет аварийную загрузку SDL через multimedia
Notcurses в окружениях с несовместимым SDL2 compatibility runtime.
