# Документация Aniparser Core

Этот индекс помогает понять, какой документ открыть для конкретной задачи.
Новый разработчик может начать с [README](README.md): там есть сборка, запуск и
готовый пример клиента на Python.

- [Архитектура](docs/ARCHITECTURE.md) — модули и путь запроса от клиента до
  внешнего API и обратно.
- [API-клиент](docs/API.md) — HTTP-запросы к yani.tv, ошибки, таймауты и
  параметры поиска.
- [Справочник моделей](docs/API_MODELS.md) — поля C++-моделей и соответствующие

- [Кэш](docs/CACHE.md) — что и как долго сохраняется в процессе сервера.
- [Сервер и IPC](docs/SERVER.md) — обработчики запросов, транспорт и ответы.
- [Формат IPC](src/server/IPC.md) — компактная спецификация JSON Lines.
- [Структуры и сериализация](docs/STRUCTURES.md) — что пересекает границы

- [Разработка](docs/DEVELOPMENT.md) — сборка, цели CMake, ручные проверки и
  безопасный порядок изменений.

## Быстрое понимание проекта

1. `src/api/` знает про HTTP/API yani.tv и превращает JSON API в C++-модели.
2. `src/core/` запрашивает API в фоновых потоках и хранит последние значения
   в памяти процесса.
3. `src/server/` зовёт Core и отправляет JSON клиентам через IPC.
4. `tui/` — один из клиентов. Он не подключается к Core напрямую.

Перед изменением протокола сначала прочитайте IPC-спецификацию. Перед
изменением полей модели проверьте `src/api/models.def` и обновите справочник
моделей. Перед изменением поведения кэша сверяйтесь с `src/core/core.cpp`:
именно код, а не документ, задаёт фактическое поведение.
