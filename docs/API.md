# API и модели

Полный список полей всех 56 структур из `models.def` вынесен в [каталог API-моделей](API_MODELS.md). Сквозные границы модулей и порядок вызовов описаны в [архитектуре](ARCHITECTURE.md).

### Модельный слой

`src/api/models.def` — единый список структур и полей API. Макросы в `models.hpp` создают C++-структуры, а `json.hpp` использует тот же список для `from_json`/`to_json`. Это уменьшает расхождения между полями модели и сериализацией. Параметры поиска объявлены отдельно в `src/common/types.hpp` как `yani::SearchInput`; каждое поле опционально, чтобы отличать не заданный фильтр.

Модели покрывают подробную запись аниме, упрощённую запись для результатов поиска, элементы feed и расписания. В подробной записи есть, среди прочего, статус, URL и варианты постера, рейтинги, тип, описание, возрастной рейтинг, внешние идентификаторы, создатели, студии, видео, жанры, порядок просмотра, переводы, ограничения, эпизоды, скриншоты и позиции в топах. Feed описывает новые аниме, объявления, рекомендации, карусель, расписание и коллекции. Точный перечень полей находится в `models.def` и намеренно не дублируется в коде преобразования Cache.

`yani_get<T>` обрабатывает пропущенное/null поле через значения по умолчанию, заданные `yani_null_value`. Для числового поля допускает JSON-число или строку, полностью разбираемую через `from_chars`; для `std::string` принимает строку или число (число сохраняется как JSON-текст); для вектора строк принимает массив строк/чисел. Остальные значения передаёт nlohmann-json. Ошибки оборачиваются именем API-поля и типом JSON. Null-маркеры отдельных типов — sentinel-значения, например `INT64_MIN` для `int64_t`, `-1` для `double`, `true` для bool; пустые строки и векторы остаются пустыми.

### HTTP-клиент

`api.hpp` предоставляет `getAnime`, `searchTitles`, `getFeed`, универсальный `get`, а также Async-варианты с `std::future<std::expected<T, ApiError>>`. Реализация находится в `api.cpp` и использует CPR. Параметры поиска превращаются в query-параметры; списки значений соединяются запятыми. Anime запрашивается по `anime/{alias_or_id}` с параметром `need_videos`. Поиск выполняется на `anime`, feed — на `feed`, опциональный `watches` также кодируется через запятую. Каждый запрос передаёт заголовок `Lang: ru`.

Общий разбор ответа отдельно проверяет сетевую ошибку CPR, JSON-синтаксис и HTTP-код 2xx. Для ошибки JSON-поля или структуры возвращается `ApiError` с HTTP-статусом и телом ответа. Async-адаптер запускает CPR callback-запрос и завершает promise результатом конвертации; исключения преобразования не выходят наружу. Синхронные методы остаются доступны, но основной Core-путь пользуется Async вариантами. Учтите, что HTTP-клиент обращается к внешнему API; без доступной сети реальные ответы не гарантированы.

Параметры `SearchInput`, поддерживаемые в модели и IPC JSON, перечислены ниже. Имена используются как имена полей JSON; отсутствующие и `null` значения фильтр не задают.

| Поле | Тип | Назначение на уровне API |
| --- | --- | --- |
| `studio_ids`, `director_ids`, `worldart_ids`, `mal_ids`, `kp_ids`, `shikimori_ids`, `ids` | `vector<int64_t>` | Фильтры по ID сущностей/аниме. |
| `q` | `string` | Текстовый поисковый запрос. |
| `min_age` | `vector<int64_t>` | Допустимые значения возрастного рейтинга. |
| `max_rating_counters`, `min_rating_counters` | `int64_t` | Верхняя/нижняя границы числа голосов рейтинга. |
| `season`, `status`, `types`, `exclude_genres`, `genres` | `vector<string>` | Сезоны, статусы, типы и включаемые/исключаемые жанры. |
| `max_rating`, `min_rating` | `double` | Верхняя/нижняя границы рейтинга. |
| `ep_to`, `ep_from`, `to_year` | `int64_t` | Границы по эпизодам и году. |
| `sort_forward` | `bool` | Направление сортировки. |
| `sort` | `string` | Поле/режим сортировки API. |
| `offset`, `limit` | `int64_t` | Смещение и количество результатов. Core принудительно задаёт limit 10 для своей пагинации. |

Списки преобразуются CPR в одну строку со значениями, соединёнными запятой; числа конвертируются через `std::to_string`, bool — в `true`/`false`. Валидация допустимых значений фильтров API-клиентом не выполняется.
