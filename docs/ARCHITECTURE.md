# Архитектура

Проект состоит из трёх слоёв сервера, общего слоя моделей и отдельного
клиента. Слои разделены, чтобы TUI или другой клиент не зависел от деталей
HTTP и хранения данных.

```text
┌────────────────────┐       JSON Lines        ┌──────────────────────┐
│ TUI / ваш клиент   │ ◀─────────────────────▶ │ IpcServer            │
└────────────────────┘                          │ src/server           │
                                                └──────────┬───────────┘
                                                           │ вызовы методов
                                                ┌──────────▼───────────┐
                                                │ Server               │
                                                │ фасад + сериализация │
                                                └──────────┬───────────┘
                                                           │
                                                ┌──────────▼───────────┐
                                                │ Core                 │
                                                │ кэш + очередь задач  │
                                                └──────────┬───────────┘
                                                           │ HTTP
                                                ┌──────────▼───────────┐
                                                │ API yani.tv / Kodik  │
                                                └──────────────────────┘
```

## Каталоги

| Путь | Что в нём находится |
| --- | --- |
| `src/api/` | HTTP-клиент, JSON-модели сайта, Kodik extractor и реестр video extractors. |
| `src/common/` | Типы, используемые более чем одним модулем, например `SearchInput`. |
| `src/core/` | Кэш в памяти процесса, TTL, объединение частичных данных и пул фоновых задач. |
| `src/server/` | Фасад `Server`, POSIX socket/Windows named pipe и JSON IPC. |
| `src/app/` | Ручной исполняемый пример и offline-проверки. |
| `tui/` | Linux TUI-клиент. Подключается к серверу только через IPC. |
| `docs/` | Этот справочник. |
| `out/` | CMake build tree; его не следует коммитить. |

## Один запрос по шагам

Например, клиент отправил `getAnime` с `anime_id: 771`.

1. Клиент записывает JSON и `\n` в открытый IPC stream.
2. `IpcServer` читает полную строку, разбирает JSON, проверяет `method` и
   обязательное поле.
3. `Server` передаёт запрос в `Core`.
4. Core под mutex получает текущий снимок и решает, истёк ли его пятиминутный
   TTL. Callback с текущим снимком вызывается сразу.
5. Если записи нет или она устарела, Core добавляет HTTP-задачу в очередь.
   Worker вызывает `yani::getAnime` из `src/api/api.cpp`.
6. После успешного ответа Core обновляет кэш и вызывает callback повторно,
   пометив значение как обновлённое.
7. IPC отправляет клиенту JSON-событие `anime.updated` с тем же `id`.

При ошибке API старый снимок остаётся в кэше. Для Anime клиент получает
`anime.updated` с `ok:false` и `error`. Для Feed/Search текущая реализация не
отправляет событие при неудачном API обновлении; подробность ошибки остаётся в
логе сервера.

## Главная граница: JSON

IPC отправляет полные самодостаточные JSON-значения. Строки и векторы живут на
стороне клиента после получения. Между процессами не передаются адреса,
указатели, C++-объекты, shared memory, дескрипторы кэша или команды освобождения.

У API-модели Anime поле называется `videos` и хранит плоский список видео.
Перед отправкой клиенту `Server::animeToJson` заменяет его на:

```text
players[] → dubbers[] → episodes[]
```

В эту структуру попадают только записи с поддержанным iframe-плеером и
непустыми названиями плеера/озвучки. Эпизоды сортируются численно по номеру.
Это преобразование относится к IPC-сериализации; API-модель в `src/api/`
остаётся с полем `videos`.

## Почему кэш находится в Core

Core централизует конкурентный доступ, TTL и объединение сведений из поиска и
feed. Server не хранит копию кэша и не передаёт клиенту ссылку на него. TUI
получает snapshot, а при обновлении заменяет или объединяет его локально.

Подробнее см. [Core](CORE.md), [кэш](CACHE.md) и [IPC](../src/server/IPC.md).
