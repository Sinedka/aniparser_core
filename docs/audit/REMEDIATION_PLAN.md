# Безопасная последовательность исправлений

> Исторический отчёт до исправлений: строки, hashes и результаты ниже относятся
> к исходному снимку аудита. Последующие изменения и актуальные проверки описаны
> в [REMEDIATION_STATUS.md](REMEDIATION_STATUS.md).


Этот план не означает разрешения автоматически менять исходники. В рамках
аудита созданы только документы и дополнен AGENTS.md. Делать небольшие PR,
каждый с отдельным воспроизведением и критерием приёмки. Не смешивать смену
формата данных, транспорта и рефакторинг многопоточности.

## 0. Зафиксировать базу

- Сохранить существующие пользовательские изменения отдельно от будущих
  исправлений. Аудит относится к working tree, а не только к HEAD.
- Зафиксировать текущие fixtures JSON Lines и `history.json` v1–4. Для
  воспроизведений использовать только disposable `ANIPARSER_DATA_DIR` в out.
- Ввести запускаемые regression cases для исправляемых дефектов. Допустим
  небольшой offline executable по образцу `--self-test`; не требуется сразу
  подключать тяжёлый test framework. Существующие 10 checks слишком узкие.
- Сначала исправить AUD-005 и получить реальную Windows-сборку. Совпадение
  списка методов Unix/Windows само по себе недостаточно.

## 1. Защитить пользовательские данные

**AUD-018 → AUD-001**, затем при необходимости **AUD-019**.

Сначала loadState должен отличать пустой новый каталог от отказа загрузки.
Иначе тестирование других ошибок может незаметно уничтожить исходный файл.
После этого определить семантику failed save: ошибка клиенту, что происходит
с in-memory mutation, возможен ли retry, когда увеличивается revision и
отправляется событие. Result/error предпочтительнее bool с двумя смыслами
«невалидно» и «не записано».

Не начинать с переписывания persistence в базу данных. Имеющийся JSON + atomic
replacement достаточен при явных ошибках и защищённом recovery. Durability
fsync добавлять после определения требований; это отдельная гарантия.

**Приёмка:** старые v1–4 читаются; неизвестная версия и повреждённый файл не
перезаписываются; create/open/write/rename failure видны клиенту; restart
восстанавливает только действительно подтверждённые сохранения. Оба транспорта
имеют одинаковый контракт ошибки. Fixtures не используют реальные данные.

## 2. Устранить зависания и ошибки жизни ресурсов

Независимыми небольшими изменениями: **AUD-004**, **AUD-006**, **AUD-003**.
Затем согласованно исправить **AUD-002**, **AUD-010**, **AUD-024**.

Сначала сделать stop прерывающим I/O и убрать listener race; без этого
stress-тесты следующих шагов будут плохо завершаться. Далее освобождать
завершённые соединения и обрабатывать отказ создания worker. Затем вынести
callbacks из locks сохранения, сохранив упорядочивание событий.

Для очереди выбрать явное поведение при перегрузке. Неблокирующий try-submit
может быть достаточен, но каждый caller обязан сбросить updating и завершить
ожидание ошибкой. Не заменять deadlock unbounded очередью: это другая форма
отказа. Не менять recursive mutex, detach threads или raw close наугад.

**Приёмка:** reentrant/throwing callbacks; медленный читатель; reconnect loop;
насыщенный пул; stop во всех этих состояниях; не осталось вечных флагов.
ASan/UBSan на полностью пересобранных целях и отдельный TSan run. Все тесты
ограничены deadline, чтобы зависание было результатом проверки, а не зависшим CI.

## 3. Исправить контракты полей и свежести

**AUD-007 → AUD-008 → AUD-009**; **AUD-012** можно делать отдельным PR.

Сначала покрыть missing/null/sentinel merge. Затем разрешить обновление общих
полей у full-card, сохранив details/videos и смысл timestamps. После этого
отделить completeness videos от обычной freshness. Не менять всю схему на
optional сразу: это затронет много wire-ответов и пользовательский код.

Числовую валидацию делать до преобразований JSON. Сохранить документированные
лимиты, но явно решить, отклонять ли невалидный limit или clamp-ить; отрицательные
и дробные ID нельзя незаметно переводить в другое значение.

**Приёмка:** partial/full/search/feed последовательности, coalescing,
false→true need_videos, свежий callback и повторный snapshot не противоречат
друг другу; ID ordering и независимость прогресса от коллекций сохранены.

## 4. Восстановить устойчивость TUI

**AUD-013**, **AUD-014**, **AUD-016** — отдельные малые исправления.
**AUD-015 и AUD-025** делать согласованно: замена full snapshot должна сразу
безопасно пересчитать выбор на всех зависимых экранах. Затем **AUD-017**.

Сначала тестировать на mock IPC без сети. Для выбора достаточно устойчивых
имён/ID и проверок границ; переписывать UI на новую framework не требуется.
Ввести loading/error/disconnected, обеспечить RAII Notcurses и deadline request.

**Приёмка:** кириллица/emoji и Backspace; null→success/error; исчезновение всех
плееров, сокращение списка, reorder; Enter/Esc после update; остановка сервера;
q и resize. Ручная проверка с сервером и screenshots для PR с видимыми изменениями.

## 5. Закрыть остальные ограничения контракта

- **AUD-011:** terminal Search/Feed error, очистка stream ID и refreshing.
  Изменение протокола согласовать в обоих transport-ах, IPC docs и клиентах;
  при несовместимости синхронно повысить hello version и TUI check.
- **AUD-023:** сохранить status/data fallback попыток AniLibria; mock HTTP
  покрывает transport error, 404/429/500, malformed JSON и успешный fallback.
- **AUD-020:** определить явную политику save_data retention/delete и лимиты
  строк, не удалять пользовательский прогресс молча при removeHistory.

Live smoke provider checks запускать отдельно от offline regression tests.
Успешный mock не доказывает, что текущий HTML/JS/API провайдера совместим.

## 6. Сопровождение после исправления поведения

**AUD-021**, **AUD-022** имеют низший приоритет. Устранение копий dispatcher
оправдано после regression fixtures для обоих транспортов. Legacy test.cpp
не удалять без отдельного согласования. Пустые cmake modules не заменяют
настоящие compiler flags/проверки; внедрение CI или новых зависимостей —
отдельное решение владельца проекта.

## Базовая проверка каждого PR

```sh
cmake -S . -B out/Debug -DCMAKE_BUILD_TYPE=Debug
cmake --build out/Debug -j2
out/Debug/src/app/my_app --self-test
git diff --check
```

При изменении C++ запускать clang-format только на изменённых файлах.
Дополнить эти команды конкретным regression case из FINDINGS; десять штатных
checks не являются достаточным доказательством исправления сохранений или races.
Сообщать платформу, результаты, сетевые и ручные проверки отдельно.
