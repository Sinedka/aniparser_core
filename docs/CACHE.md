# Кэш и сохранённые данные

В проекте есть два разных вида хранения:

- **Anime, Search и Feed** живут только в памяти Core. При остановке процесса
  они очищаются.
- **История, избранное, статусы просмотра и позиция эпизода** сохраняются
  SaveManager в `history.json`.

## Обновление API-данных

Anime, Feed и страница Search считаются свежими пять минут после успешного
ответа API. Подписка сначала немедленно возвращает текущий snapshot, включая
пустой или частичный. Если нужной записи нет или её TTL истёк, Core запускает
обновление в фоне и отправляет событие при успехе. Ошибка не затирает последний
успешный snapshot.

### AnimeCache

`src/core/cache/anime_cache.hpp/.cpp` хранит динамические записи Anime в
`unordered_map<int64_t, unique_ptr<Entry>>`. Запись хранит API-модель, отметку
полноты/времени, подписки клиентов и ссылки Search-страниц. Освободить запись
можно, когда она не обновляется и на неё нет подписок или ссылок Search.
Безопасные кандидаты на удаление хранятся в очереди; лимит обычного Anime-кэша —
1024 записи, но он может временно превышаться, если все записи используются.

Результаты Search и Feed дают частичные карточки. Их общие поля сливаются с уже
имеющимися значениями, включая полную карточку; details/videos не удаляются. `subscribeAnime`
запрашивает полную модель через `getAnime(..., need_videos=true)`.

### Search и Feed

Ключ Search — сериализованные все поля `SearchInput`, включая `offset` и
`limit`. Search-страница хранит упорядоченные ID; данные карточек лежат один раз
в AnimeCache. Объём Search-кэша ограничен 256 страницами. При выдаче snapshot
Core восстанавливает строки Search из карточек; если часть карточек отсутствует,
страница обновляется через API.

Feed хранит последний `FeedResponse`. После успешного `subscribeFeed` Core
сливает доступные поля аниме из разделов Feed в AnimeCache.

### Частичное слияние

Core сериализует partial-модели во временный JSON и рекурсивно сливает поля.
Пустые строки, нули, пустые массивы/объекты, `null` и missing-сентинелы
(`INT64_MIN`, floating-point `-1`) не затирают уже полезные значения. Это эвристика: если ноль имеет специальный смысл для поля, обновляйте
правила слияния точечно.

## Коллекции пользователя

`HistoryCollection`, `FavoritesCollection` и `AnimeStatusCollection` используют
общего родителя `AnimeCollection` из `src/core/cache/anime_collection.hpp`.
Базовый класс хранит уникальные ID в двусвязном списке и hash-индексе
`anime_id → iterator`, чтобы перемещать и удалять элементы за ожидаемое O(1).
Каждый список ограничен 1000 ID; повторное добавление перемещает ID в начало.

История, избранное и статусы — разные списки. Четыре статуса (`planned`,
`watched`, `completed`, `dropped`) взаимоисключающие: добавление в один удаляет
ID из остальных статусов. Это не удаляет его из истории или избранного.

IPC-подписки этих списков постраничные: сервер возвращает только указанные
`offset`/`limit` (максимум 50). Метаданные карточек страницы берутся из
AnimeCache. Если карточка отсутствует или устарела, Core обновляет только ID
этой страницы через Search API. Для недавно проверенного отсутствующего ID
есть отрицательный кэш на пять минут, ограниченный 1000 ID.

## SaveManager

`src/core/cache/save_manager.cpp` сохраняет пользовательские списки и
`AnimeSaveData` атомарной заменой файла `history.json`. Формат версии 4 содержит
`history`, `favorites`, `anime_states` и `save_data`. Читаются и прежние версии
1–3, поэтому обновление сохраняет старые данные истории, прогресс и избранное.
Состояния в старом файле отсутствуют и появляются после записи версии 4.

Путь можно задать через `ANIPARSER_DATA_DIR`. Иначе используются стандартные
каталоги платформы: Linux — `$XDG_DATA_HOME/aniparser` или
`$HOME/.local/share/aniparser`; macOS — `~/Library/Application Support/AniParser`;
Windows — `%APPDATA%/AniParser` с резервом `%LOCALAPPDATA%/AniParser`.
Каталог предназначен для одного процесса сервера.

См. [описание Core](CORE.md) и [формат коллекций IPC](../src/server/IPC.md).

Запись использует эксклюзивный временный файл, на Unix — fsync файла,
rename и fsync каталога; на Windows — FlushFileBuffers и MoveFileExW.
Файл неизвестной версии или с ошибкой чтения не перезаписывается.
Прогресс ограничен 10 000 новыми ID без автоматического удаления старых;
явное удаление — `removeAnimeSaveData`. См. транзакционный контракт в CORE.md.
