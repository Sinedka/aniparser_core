# Кэш данных

Кэш реализован обычными C++-контейнерами внутри `Core`. Он нужен, чтобы клиент
сразу увидел последние известные данные, а API-запрос выполнялся отдельно.
Кэш не записывается на диск и очищается при завершении сервера.

## Политика обновления

- TTL для Anime, Feed и страницы Search — 5 минут от успешного ответа API.
- Запрос к свежей записи возвращает её и не запускает обновление.
- Запрос к отсутствующей или устаревшей записи сразу возвращает snapshot,
  затем запускает API и при успехе отправляет update callback.
- Неуспешный запрос не заменяет последний успешный snapshot.
- Записи, пришедшие только из Feed/Search, являются частичными: их `refreshed_at`
  не означает, что полная карточка Anime уже загружена.

## Три части кэша

### Anime

Map индексируется `anime_id`. Результат поиска или feed создаёт частичный
`AnimeResult`: например, название, описание, постер, оценку, год, тип и внешние
ID. При таком обновлении непустые значения сливаются с тем, что уже было.
Частичные записи не перезаписывают запись с `has_full_details == true`.

При `getAnime` сервер сразу отдаёт имеющуюся частичную карточку, а затем
запрашивает полные подробности с `need_videos=true`. При успехе API-результат
заменяет запись и получает полный статус. Это отдельная модель от IPC-представления:
Server группирует сырые `videos` в `players` перед отправкой клиенту.

Кэш удерживает примерно до 1024 Anime-записей. При давлении он удаляет старую
запись, если у неё нет активного обновления и ожидающих callbacks. Неизбежно
активные записи могут временно превысить этот предел в пути `getAnime`.

### Search

Ключ — сериализованный набор **всех** полей `SearchInput`, включая `offset` и
`limit`. Разные страницы и разные фильтры — разные записи. Успешная страница
сохраняется и одновременно заполняет Anime-кэш краткими сведениями из строк.
Старые Search-страницы очищаются при успешном поиске; map ограничен примерно
256 записями с удалением старейшей при заполнении.

### Feed

Хранится один последний `FeedResponse`. После успешной загрузки Feed Core
заполняет Anime-кэш данными из `new`, `announcements`, `recommends`,
`top_carousel.items`, `collections[].animes`, `new_videos`, `last_watches` и
`schedule`. Для последних четырёх типов часто доступны лишь название,
описание, постер, URL и ID.

## Частичное слияние

Для partial моделей Core сериализует модель во временный JSON и рекурсивно
добавляет значения. Пустые строки, числа `0`, пустые массивы/объекты и `null`
не затирают полезное значение. Для остальных значений новая информация
заменяет старую. Это удобная эвристика, но ноль может быть настоящим значением
API: если поле требует строгой семантики, обновите правила слияния и добавьте
покрытие на эту ситуацию.

## Клиентская сторона

IPC не предоставляет внутренние map. Клиент владеет полученным JSON и может
сохранить его локально. TUI показывает немедленную запись и сливает поздний
`anime.updated` с локальной карточкой, чтобы не потерять поля из более полного
снимка. Удалять или освобождать данные на сервере не требуется.
